## INFRASTRUCTURE — isolated worker `ca8599e`
### Point 3 — venv isolation · **PASS**
Dedicated **Python 3.12.10** venv outside the AI Trader repo; deps **pinned + hash-locked** (`requirements.lock`, `pip install --require-hashes`: numpy 2.5.1 / pandas 3.0.3 / dateutil / six / tzdata, each `--hash`); non-editable console-script entrypoint (`ve-tower-worker`); launch via isolated venv with `-I`, cleared `PYTHONPATH`, CWD outside repo; **startup audit** (`enforce_startup_audit`, runs first) refuses to start if any AI-Trader repo path is in `sys.path` or any of the 9 host names is pre-loaded; `verify_tower_wheel.py` is **fail-closed** (`PINNED_TOWER_WHEEL_SHA256 = None` → refuses to install any wheel until the pin is recorded — this is precisely the gate STAGED_INSTALL opens).
### Point 6 — main-process isolation · **PASS**
`ve_tower` is **not imported** anywhere in `ai_trader` (main); the main-side IPC (`tower_protocol.py`) is **pure stdlib** (json/dataclasses — no numpy/pandas, no vendored bare names); the worker imports **nothing** from `ai_trader`; the worker's `decision.py` reaches **no** broker/legacy/market_intelligence; `tower_client.py` imports none of them (the 3 grep hits are its docstring disclaiming them). So the tower's bare names never enter the main `sys.modules`; the 5 live processes are untouched.
### Point 4 — IPC · strong core, one bound missing
Loopback TCP, 4-byte big-endian length prefix + `json.dumps(sort_keys=True)`; **no pickle, no eval/exec**; `MAX_PAYLOAD_BYTES = 4 MiB` enforced on **send and on receive — the length prefix is checked BEFORE allocating/reading**, bounding memory against a hostile prefix; full fail-closed field validation (`parse_request`/`parse_response`) before any object is trusted; the **client verifies response identity** (request_id / market_event_id / event_fingerprint) and distinguishes `STALE_RESPONSE` (same request_id, different event) from `RESPONSE_IDENTITY_MISMATCH`; worker is stateless (idempotent by construction). **🟠 FINDING:** the **client idempotency cache is UNBOUNDED** — `TowerClient._cache` grows one entry per unique `(request_id, event_fingerprint)` with no eviction/limit (confirmed: 5,000 entries accepted; no `max`/`evict`). Over a live-shadow run this leaks memory in the main process. **🟡 Minor:** loopback is the **default**, not enforced — `--host` accepts `0.0.0.0`; the server should reject a non-loopback bind.
### Point 5 — worker identity handshake · **🔴 MISSING (the decisive finding)**
There is **no handshake**. The worker exchanges no `ve_tower version / wheel SHA / contract versions / session identity`; the client verifies only `protocol_version` + the echoed request identity. **Confirmed reproducibly:** a fake server on the port speaking `protocol_version="1.0"`, echoing the request's `request_id/market_event_id/event_fingerprint`, with `tower_version="WRONG-9.9.9"` and **fabricated `n3_output`/`n4_output`**, is **accepted by the client as a valid `TowerN3N4Result`.** So:
- **Wrong connection** (an accidental other local process on port 8765 that speaks the schema) → **not detected.**
- **Wrong version** (an *old* `ve_tower` worker, or a different wheel/contract, on the port) → **not detected** (protocol-version mismatch is caught; ve_tower/wheel/contract identity is not).
The CEO required both to be detected ("*conexiunea greșită și versiunea greșită TREBUIE detectate*"). The worker is verified at **startup** (wheel-SHA pin + startup audit), but the **client has no way to confirm the process it connected to is that verified worker.** This is on the decision path (a wrong worker feeds fabricated N3/N4 into the decision), so it must be closed before the Phase-2 real-path review.

## VERDICT — **TOWER_HANDOFF_CONDITIONAL** (not the automatic STAGED_INSTALL_AUTHORIZED)
The artifact (transactional bootstrap genuinely fixed, byte-identical, N3/N4 unchanged) and the isolation (separate hashed venv, startup audit, clean main isolation, fail-closed wheel pin) are **sound**. But the IPC layer has a reproducible decision-path gap (no worker-identity handshake → wrong/old artifact accepted) and an unbounded cache — real defects, so per the rule this is CONDITIONAL, not a clean pass. **Conditions to reach `TOWER_ARTIFACT_PASS · STAGED_INSTALL_AUTHORIZED`:**
1. **Add a worker-identity handshake** (or per-response identity block) the client verifies: `ve_tower` version + **wheel SHA-256 / pin** + N3/N4 **contract versions** + worker **session id**; reject a wrong-artifact/wrong-version/wrong-session peer with a specific reason code. This detects wrong-connection and wrong-version, as the CEO requires (not a security boundary against a local admin — a *detection* of the wrong process).
2. **Bound the idempotency cache** (size limit + eviction, or scope it per event and clear it).
3. **Enforce loopback bind** (reject non-`127.0.0.1` host).
On confirmation I re-verify the handshake against the five point-5 tests (port occupied · fake server · old worker on port · handshake with a different artifact hash · reconnect after restart) and the cache bound, then grant the staged install. **Phase 2** (the real IPC→worker→N3→N4→Router→EV→N6→Risk→broker-BLOCKED path) follows the controlled install, per the CEO's plan.
