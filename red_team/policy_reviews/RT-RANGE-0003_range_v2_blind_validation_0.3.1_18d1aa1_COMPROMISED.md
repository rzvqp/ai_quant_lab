The channel/range **classification** is correct (channels → `CHANNEL_UP`/`CHANNEL_DOWN`, never `RANGE_STATE`), so this is a naming/granularity divergence, not a misclassification. **But** the ratified spec specifies these as distinct reason codes, the implementation collapses/renames them, and **no ratified source authorizes the mapping** (whether the exact strings are binding-by-name or descriptive is undetermined). Per §3's rule ("do not invent them and do not treat them as automatically non-blocking"), this cannot be resolved exclusively from ratified sources → **RANGE_V2_CONTRACT_AMBIGUITY_REASON_CODES**. Minimal fix (for VE/Statistician, not implemented by me): either the Statistician ratifies the `IS_CHANNEL`+`structure_class` / `INPUT_UNAVAILABLE` mapping as contract-equivalent, or VE emits the exact specified reason codes.
